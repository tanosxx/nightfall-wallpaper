# Пакеты сцен Nightfall

В v16 каталог доступен в приложении и на [сайте](https://tanosxx.github.io/nightfall-wallpaper/). Приложение содержит встроенный «Ночной рубеж»; остальные сцены скачиваются отдельно. Установленные пакеты остаются на компьютере и работают без сети. При обновлении с полной коллекции v15 установщик переносит имеющиеся сцены в локальную библиотеку.

## Для пользователя

Откройте библиотеку Nightfall из значка в панели GNOME, затем **Каталог**. При первом открытии этой вкладки приложение загружает список и небольшие обложки. На карточке указаны автор, лицензия, версия и размер. Нажмите **Скачать**, дождитесь проверки и выберите сцену во вкладке **Установлено**.

- **Обновить** повторно загружает список каталога. При отсутствии сети показывается последняя сохранённая копия, если она есть.
- **Обновить сцену** появляется, если в каталоге доступна более новая версия установленного пакета. Обновления устанавливаются по запросу пользователя.
- **Отменить** останавливает текущую загрузку. Неполный пакет не становится установленной сценой. Если установка уже успела завершиться, приложение покажет сохранённую сцену и сообщит об этом.
- **Удалить** убирает скачанную сцену с компьютера. Если она выбрана, Nightfall сначала переключается на встроенный город. Сам встроенный город удалить нельзя.
- **Каталог → Установить из файла…** принимает ZIP-пакет сцены, скачанный с сайта или полученный для проверки. Это пакет сцены, а не ZIP всего расширения.

Сайт не записывает файлы непосредственно в библиотеку приложения. Кнопка скачивания сохраняет архив обычным способом через браузер; затем импортируйте его через приложение.

Данные находятся в `$XDG_DATA_HOME/nightfall/scenes/` (обычно `~/.local/share/nightfall/scenes/`), кэш каталога и обложек — в `$XDG_CACHE_HOME/nightfall/` (обычно `~/.cache/nightfall/`). Для работы рабочего стола после установки интернет не нужен. Настройки выбора и паузы по-прежнему хранятся в GSettings.

## Что содержит пакет

Формат 1 — ZIP с `scene.json` в корне, изображениями PNG, разрешёнными JSON-данными и уведомлениями о лицензии. Распакованная структура выглядит так:

```text
scene.json
LICENSE
NOTICE.md
ASSETS.md
assets/
  polar.png
  ...необходимые слои и маски...
```

Исполняемых файлов, GJS/JavaScript, Python, HTML и произвольных шейдеров внутри пакета нет. Код отрисовки поставляется с приложением и проходит обычную проверку изменений в репозитории.

Основные поля `scene.json`:

| Поле | Назначение |
| --- | --- |
| `formatVersion` | `1` — версия формата пакета. |
| `id` | Постоянный уникальный идентификатор: строчная латинская буква, затем буквы, цифры или дефис; всего до 64 символов. |
| `version` | Положительное целое число. Увеличивается при изменении содержимого выпущенного пакета. |
| `name`, `subtitle`, `description` | Название, краткая подпись и описание обычным текстом. |
| `author`, `license` | Автор и лицензия материалов. |
| `renderer` | Один из встроенных движков: `nightfall`, `polar`, `station`, `abyss`, `junction`, `cloudcity`, `titans`. |
| `image` | Путь к основной композиции: `assets/имя.png`. |
| `width`, `height` | Для формата 1: `1672`, `941`. |
| `control` | `weather`, `flow` или `activity`. |
| `weatherLabel` | Название регулятора интенсивности. |
| `files` | Словарь путей; для каждого файла указаны `sha256` и `bytes`. Сам `scene.json` в список не входит. |

Сборщик создаёт манифест и контрольные суммы автоматически. Не редактируйте опубликованный архив, сохраняя прежнюю версию: пакет с тем же номером и другим содержимым будет отклонён. Переход на более старую версию также отклоняется.

Установщик ограничивает размеры архива, файлов и распакованных изображений, проверяет PNG, JSON, обязательные слои, пути и SHA-256. Символьные ссылки и выход за каталог сцены не допускаются. Сначала пакет проверяется во временной папке, затем целиком подключается к библиотеке. Контрольная сумма проверяет целостность; происхождение работ и условия использования проверяются при принятии в публичный каталог.

## Возможности формата 1

Пакет может иметь собственный `id` и использовать существующий движок. Однако расположение окон, дыма, транспорта и других эффектов в этих движках связано с геометрией исходной композиции. Простая подмена фотографии с совершенно другими зданиями не создаёт подходящую анимацию автоматически.

Поэтому первый формат подходит для подготовленных композиций и совместимых вариантов с сохранением размещения эффектов. Для новой геометрии, новой модели движения или нового движка нужен pull request с кодом приложения и визуальной проверкой. Движок не загружается из пакета и не исполняется автоматически из каталога. Для нового идентификатора сайт показывает обложку и скачивание; живой браузерный предпросмотр добавляется отдельным проверенным изменением.

## Подготовка своей сцены

1. Обсудите идею в [Issues](https://github.com/tanosxx/nightfall-wallpaper/issues), особенно если требуется новая геометрия или эффекты.
2. Подготовьте PNG-композицию 1672 × 941 и необходимые маски/атласы для выбранного движка. Проверьте перспективу, края масок и полный цикл анимации.
3. Добавьте ресурсы в `assets/`, а небольшую PNG-обложку — в `catalog/previews/`. Обложки штатных сцен имеют размер 480 × 270; сборщик принимает PNG меньше 1 МБ.
4. Добавьте запись с новым `id` в `catalog/scenes.json`. Используйте [шаблон](../catalog/scene.example.json): он описывает автора, лицензию, ресурсы, обложку и `metadata` для нового идентификатора. Не меняйте `id` уже опубликованной сцены.
5. Укажите происхождение материалов и применимые лицензии. Для созданных ИИ изображений укажите факт генерации. Обновите уведомления проекта, если добавляете материалы с особыми условиями.
6. Соберите пакеты и проверьте свою сцену локально:

```bash
python3 scripts/build-scene-packs.py
```

Сборщик создаёт `dist/scenes/nightfall-scene-<id>-v<version>.zip`, индекс `dist/catalog/index.json` и обложки. Откройте созданный ZIP через **Каталог → Установить из файла…**. Это установит сцену в вашу пользовательскую библиотеку, поэтому используйте новый идентификатор для экспериментов.

Для проверки без изменения своей библиотеки можно установить пакет в отдельную временную папку:

```bash
nightfall_pack_check="$(mktemp -d)"
python3 extension/nightfall@local/scene-manager.py \
  --data-dir "$nightfall_pack_check" install-file dist/scenes/nightfall-scene-polar-v1.zip
python3 extension/nightfall@local/scene-manager.py \
  --data-dir "$nightfall_pack_check" list
```

В примере используется штатная полярная сцена; замените имя ZIP своим. Команды проверяют файлы и локальный реестр, не включают обои и не меняют GSettings. Общие проверки проекта описаны в [CONTRIBUTING](../CONTRIBUTING.md).

## Публикация в общем каталоге

Отправьте pull request с исходными ресурсами, записью каталога, происхождением материалов и кадрами или коротким роликом. Сопровождающий проверяет содержимое, лицензии, внешний вид и нагрузку. После принятия изменения сборка публикует ZIP-пакеты в GitHub Releases, а индекс и обложки — на GitHub Pages. Тогда сцена появляется на сайте и после обновления каталога в приложении.

Прямой автоматической публикации из приложения нет. Обычный участник предлагает изменение через GitHub; доступ к выпуску и общему каталогу остаётся у сопровождающих. Отдельный сервер и внешний сервис хранения для этого процесса не требуются.

## Для разработчиков

Менеджер `extension/nightfall@local/scene-manager.py` использует Python 3 из системы, не запускается внутри GNOME Shell и возвращает JSON в stdout. Ошибка возвращает ненулевой код завершения и `{ "ok": false, "error": "…" }`.

| Команда | Действие |
| --- | --- |
| `list` | Прочитать локальные сцены. |
| `refresh` | Обновить индекс; при недоступности сети вернуть сохранённый с `cached: true`. |
| `preview ID` | Получить проверенную обложку в кэше и вернуть её локальный `path`. |
| `install ID` | Скачать и проверить пакет из текущего каталога. |
| `install-file PATH` | Проверить и установить локальный ZIP-пакет. |
| `remove ID` | Удалить внешнюю сцену из локальной библиотеки. |
| `import-bundled PATH` | Перенести сцены из старого полного расширения; используется установщиком. |

`--data-dir PATH` перед командой позволяет направить данные и кэш в отдельную папку для тестов. Менеджер не переключает GSettings: интерфейс после изменения библиотеки увеличивает `library-revision`, а Shell перечитывает локальный список.

Индекс имеет `formatVersion: 1`, `engineVersion: 1` и массив `scenes`. В каждой записи есть метаданные, `previewUrl`, `previewSha256`, `previewBytes` и `package: {url, sha256, bytes}`. Штатный менеджер принимает индекс и обложки только с сайта Nightfall на GitHub Pages, а архивы — из GitHub Releases этого репозитория. Случайные сторонние URL в индекс не подключаются.
