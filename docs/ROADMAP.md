# Дальнейшее развитие

Это направления работы, а не перечень доступных функций или обещание сроков. Текущее поведение описано в [README](../README.md).

## Что есть в v15

- Семь сцен в одном локальном установочном пакете.
- Библиотека, переключение из панели GNOME, пауза и настройки интенсивности.
- Нативная отрисовка GJS/Cairo и браузерный предпросмотр.
- Работа рабочего стола без интернета и внешних CDN.
- Общий исходный каталог сцен, проверки упаковки и готовые ресурсы эффектов.

## 1. Общий публичный каталог

Сделать машиночитаемый индекс с идентификаторами, версиями, описаниями, небольшими превью, авторами, лицензиями и совместимостью сцен. Этот индекс смогут использовать страница GitHub Pages и приложение.

Существующий `scene-catalog.js` объединяет встроенную коллекцию, но ещё не является удалённым каталогом с управлением загрузками. Публичный браузерный предпросмотр сам по себе такой функции не добавляет.

## 2. Отдельные локальные пакеты

Отделить доверенный движок приложения от данных сцен: композиций, масок, атласов и параметров разрешённых эффектов. Описать версионируемый манифест и формат архива; добавить установку, обновление и удаление отдельных пакетов с сохранением работы без сети.

Перед подключением пакета нужны проверки структуры, путей, контрольных сумм, размера ресурсов и совместимости движка. Изменения загрузки каталога и схемы выбора сцены должны сохранить настройки существующих пользователей.

**В v15 этого нет:** приложение не скачивает сцены по отдельности и не предлагает менеджер удалённой библиотеки.

## 3. Участие сообщества

Подготовить шаблон сцены, документацию формата, небольшие примеры и автоматические проверки. Предлагаемый процесс публикации: pull request, проверка ресурсов и лицензий, просмотр сопровождающим, затем выпуск пакета и обновление каталога.

GitHub может хранить исходники, индекс и архивы; GitHub Pages — показывать коллекцию, а Actions — выполнять проверки и сборку. Отдельный сервер не нужен для такого процесса. Загрузка из приложения и самостоятельная публикация через веб-интерфейс потребуют отдельной реализации и ещё не доступны.

## 4. Граница исполнения

Первый формат скачиваемых сцен стоит ограничить данными для проверенных движков. Произвольный JavaScript/GJS сообщества нельзя автоматически исполнять внутри GNOME Shell как обычный ресурс обоев.

Если появится потребность в пользовательских движках, для неё нужно отдельно исследовать изоляцию процесса, разрешения, ограничения нагрузки и восстановление после ошибки. Проверка контрольной суммы не решает эту задачу.

## 5. Качество и совместимость

Продолжать проверку перспективы, масок, полных циклов движения и поведения на разных разрешениях. Исследовать нагрузку, превью меньшего размера и повторное использование ресурсов. Поддержка других версий GNOME потребует тестирования; текущий выпуск поддерживает только GNOME Shell 50.

Предложения можно обсуждать в [Issues](https://github.com/tanosxx/nightfall-wallpaper/issues). Изменения принимаются по правилам [CONTRIBUTING](../CONTRIBUTING.md).
