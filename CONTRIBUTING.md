# Участие в Nightfall

Предложения, исправления и новые сцены принимаются через [Issues](https://github.com/tanosxx/nightfall-wallpaper/issues) и pull request. В v16 приложение скачивает отдельные пакеты из общего каталога и устанавливает локальные ZIP. Публикация работ в общий каталог происходит после проверки pull request; автоматической загрузки работ из приложения нет.

## Сообщение о проблеме

Укажите версию Nightfall, вывод `gnome-shell --version`, выбранную сцену, разрешение экрана и действия для воспроизведения. Отметьте, где возникает проблема: на рабочем столе, в окне библиотеки или в браузерном предпросмотре. Для движения полезен короткий ролик с указанием участка кадра.

Перед публикацией уберите из журналов и снимков персональные данные. Не прикладывайте полные дампы настроек, профиль браузера, токены или домашний каталог. Для уязвимостей используйте [SECURITY.md](SECURITY.md).

## Подготовка изменений

1. Создайте ветку от актуального состояния репозитория.
2. Сформулируйте конкретное изменение: какой дефект исправляется или что увидит пользователь.
3. Внесите изменения вместе с необходимыми ресурсами и проверками.
4. В pull request опишите результат, проведённую проверку и ограничения. Для визуального изменения приложите сравнение кадров или короткий ролик.

Сборка расширения должна использовать корневую `assets/`. Не копируйте установленное расширение обратно в исходники: оно содержит сгенерированные и потенциально устаревшие файлы. Упаковку выполняет `package-extension.py`.

## Проверки

Общий сценарий проверок исходников, используемый для CI и подготовки выпуска:

```bash
bash scripts/check-source.sh
```

Он требует Node.js, системного Python 3 и GJS/Cairo; установщик и пакеты проверяются без изменения рабочего сеанса.

Node.js запускает проверки модели и каталога:

```bash
node tests/scene-catalog.test.mjs
```

Запускайте также тесты изменяемой сцены. Например, для эффектов «Пепла титанов»:

```bash
node tests/titans-timeline.test.mjs
node tests/titans-additions-assets.test.mjs
node tests/titans-suit.test.mjs
```

Для проверки готового пакета нужны GJS, Cairo и `glib-compile-schemas`:

```bash
nightfall_check_dir="$(mktemp -d)"
python3 scripts/build-scene-packs.py
python3 package-extension.py \
  --stage "$nightfall_check_dir/nightfall@local" \
  --archive "$nightfall_check_dir/nightfall@local.shell-extension.zip"
python3 scripts/check-packaged-scenes.py "$nightfall_check_dir/nightfall@local"
```

Проверка использует компактное расширение и отдельные архивы сцен из `dist/scenes`, рисует все семь сцен и проверяет движение, паузу, изменение размера и освобождение ресурсов. Она устанавливает пакеты только во временную тестовую папку и не меняет настройки рабочего сеанса. Путь к созданным кадрам выводится в терминал.

Готовый ZIP можно отдельно проверить и упаковать вместе с установщиком:

```bash
python3 scripts/verify-bundle.py "$nightfall_check_dir/nightfall@local.shell-extension.zip"
python3 scripts/package-release.py \
  --bundle "$nightfall_check_dir/nightfall@local.shell-extension.zip" \
  --output dist
```

Результат — установочный `tar.gz`, ZIP расширения и `SHA256SUMS`. Эти команды создают локальные файлы и ничего не публикуют.

Часть Python-проверок анализирует ранее созданные кадры и требует Pillow/NumPy; сценарии записи видео дополнительно используют GStreamer. Следуйте входным данным конкретного скрипта: содержимое `tests/` не является единым набором установочных команд.

## Визуальные изменения

- Посмотрите сцену целиком и увеличенный участок в браузере и нативном рендерере.
- Проверьте полный цикл анимации, включая его границу. Первые несколько секунд могут не показывать дефект.
- Сохраняйте перспективу: размер, скорость и яркость дальних эффектов должны соответствовать расстоянию.
- Маски должны защищать неподвижную геометрию. Дым не должен тянуть за собой корпус, здание или край изображения.
- Проверьте паузу, интенсивность, переключение сцены и отсутствие влияния курсора.
- Отметьте, если изменилась нагрузка или размер ресурсов. Не включайте временные атласы и дубли изображений в готовый пакет.

## Новая сцена

Начните с [формата пакетов и процесса публикации](docs/SCENE-PACKS.md) и [шаблона сцены](catalog/scene.example.json). Пакеты содержат данные и могут использовать один из встроенных движков с новым идентификатором. Геометрия эффектов в этих движках связана с исходной композицией: для нового расположения объектов или новой анимации нужны проверенные изменения кода приложения.

Держите общую модель движения независимой от браузера и GNOME, когда это позволяет реализация. Пользователь не должен получать существенно разные сцены в предпросмотре и на рабочем столе.

Не добавляйте автоматическую загрузку и исполнение JavaScript из пакетов. Нативное расширение работает внутри GNOME Shell; менеджер принимает только проверяемые изображения, данные и уведомления о лицензии. Новый рендерер и живой браузерный предпросмотр добавляются обычным pull request. Смена существующих идентификаторов затрагивает сохранённые настройки пользователей.

## Ресурсы и лицензии

Укажите происхождение новых изображений, звуков, моделей и стороннего кода, а также применимую лицензию. Для ИИ-изображений укажите факт генерации; не заявляйте права на чужие материалы. Сохраняйте сторонние уведомления об авторстве и лицензиях.

Собственные изменения предоставляются на условиях проекта, описанных в [NOTICE.md](NOTICE.md). Если у файла другие условия, явно обозначьте это. Не включайте содержимое локальных резервных копий, настройки пользователя, старые установочные архивы или личные пути в публикуемые материалы.
